# 0001. Rust as the implementation language

Status: accepted.

## Context

The existing verifiers are Scala (needs a JVM) and JavaScript (needs Node). A
tool whose point is that anyone can check a package without the producer
should be one file that runs with nothing installed. Its first library
consumer, Agent Billing Center, is Rust.

## Decision

Rust, stable, edition 2024, toolchain pinned in `rust-toolchain.toml`.
`unsafe` forbidden. Synchronous code only: no async runtime until a remote
operation exists to justify one.

The canonical JSON reader is written here rather than taken from `serde_json`.
The encoding needs exact integers of any size, refusal of fractions, unpaired
surrogates and duplicate keys, and resource limits enforced during parsing.
Upstream's Rust checker gets part of the way with `serde_json` raw values and
`bigdecimal`; a purpose-built reader of about 550 lines is smaller than the
workarounds, has no dependencies, and its every behavior is specified by this
project. `serde_json` is used only by the CLI, to print results.

## Consequences

- A third independent implementation, which is itself evidence about the
  specification's clarity.
- Protocol-critical parsing is our code to get right: it carries known-answer,
  property and corpus tests, and needs fuzzing before any release.
- Cryptography is never implemented here. SHA-256 comes from `sha2`; Ed25519
  will come from a maintained crate chosen when signatures are implemented.
